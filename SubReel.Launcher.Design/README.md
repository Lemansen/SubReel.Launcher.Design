# SubReel Launcher — главная страница

> **v15: решение разделено на проекты** (Domain / Application / Infrastructure / Design / Tests), зависимости собирает `Microsoft.Extensions.Hosting`. Структура и границы слоёв — [../ARCHITECTURE.md](../ARCHITECTURE.md), устройство представления — [MVVM.md](MVVM.md), план развития — [../ROADMAP.md](../ROADMAP.md), аудит этапа 4 — [../docs/stage4-audit.md](../docs/stage4-audit.md).
> Разделы «Итерация v5 … v13.3» ниже — **история**: имена файлов вида `MainWindow.News.cs` и `NewsConfig` относятся к версиям до MVVM и до v15 (соответствие — в таблице «Куда делся старый код» прежнего `MVVM.md`; сейчас адрес ленты новостей задаётся в `appsettings.json`).

Отдельный WPF/.NET 10 концепт-проект для переноса главного экрана из `SubReelWeb`. Основной проект `SubReel.Launcher` не изменяется.

## Новости: подключение источника SubReel

Адрес JSON-ленты задаётся в `appsettings.json` (рядом с exe) или переменной окружения `News__SubReelEndpoint`:

```json
{ "News": { "SubReelEndpoint": "https://example.com/news.json" } }
```

Пока адрес пуст, категории SubReel / лаунчер / серверы / моды показывают «источник не подключён». Формат ленты — JSON-массив:
`[{ "id": "...", "category": "subreel|launcher|servers|mods", "title": "...", "summary": "...", "body": "...", "imageUrl": "https://...", "url": "https://...", "publishedAt": "2026-10-30T12:00:00Z" }]`.

## Данные пользователя и журнал

- Настройки и аккаунты: `%AppData%\SubReel\design-settings.json` (запись атомарная, предыдущая версия — `.bak`, повреждённый файл переименовывается в `.corrupt-<время>`, а не удаляется).
- Кэш картинок и новостей: `%LocalAppData%\SubReel\cache`. Журнал: `%LocalAppData%\SubReel\logs`.

## Что есть в текущей итерации
- Тёмная оболочка с сине-голубым акцентом, скруглёнными панелями и мягкими свечениями.
- Верхняя панель: бренд, навигация, профиль и оконные кнопки.
- Центральный экран `Survival Reborn` и чип новостей.
- Нижняя панель: создание сборки, выбор версии и большая кнопка запуска.
- Плавное раскрытие индикатора подготовки рядом с кнопкой «Играть».
- Плавное появление модальных панелей с небольшим масштабированием.
- Демонстрационные окна профиля, настроек, новостей, версии и создания сборки.

## Запуск
1. Открой `SubReel.Launcher.Design.sln` в Visual Studio с поддержкой .NET 10 (нужен Windows).
2. Выбери `SubReel.Launcher.Design` как запускаемый проект и запусти через `F5`.
3. Тесты: `dotnet test` (проект `SubReel.Launcher.Tests`, работает и без Windows).

## Ограничения
Это визуальный концепт: настоящий запуск Minecraft, Microsoft/Supabase-авторизация, загрузка версий и модлоадеров пока не подключены. Сборка должна быть проверена в Windows с установленным .NET 10 SDK.


## Итерация v5

Убрана внешняя рамка-контейнер с отступом 22 px: фон теперь заполняет всю клиентскую область окна, чтобы не оставалось чёрных полос по краям. Окно остаётся без стандартного заголовка Windows, управление окном расположено в собственной шапке.


## Итерация v10 — главная страница как в веб-версии

Главный экран приведён к `SubReelWeb/app/concept/launcher` (размеры, цвета, отступы, иконки, состояния кнопок):

- Окно 1100×700, внутренний отступ 24, строки 76 / 1fr / 110, зазор 20; фон `#0C0C0F` с одним radial-свечением сверху (как `.app-shell`). Боковое свечение убрано.
- Шапка: отступы 0×28, иконки Lucide (home / compass / settings), активная вкладка и hover как у `.nav-links`, профиль-пилюля (`#0D0D0D`, аватар 32 px `#4C85FF`), блок оконных кнопок 28×28 с красным hover у закрытия.
- Центр: заголовок 48 px с вертикальным градиентом и текст приветствия из веба; чип «JAVA EDITION / SURVIVAL» и декоративная линия убраны (в вебе их нет). Кнопка новостей слева снизу (12/12) с иконкой flame, без стрелки.
- Подвал: сплошной `#111114`, кнопки высотой 48 (Layers / FolderOpen), «Создать сборку» с акцентной рамкой, «Версия» с opacity 0.7 → 1 на hover.
- «Играть» 260×64: hover — подъём на 2 px и тень; состояние `loading` (серая, «ЗАГРУЗКА...») и `ready` (свечение, «ЗАПУСК») через `Button.Tag`.
- Прогресс раскрывается на всё свободное место между левыми кнопками и «Играть» (0.6 s, easeOutQuart); полоска 8 px, `#16161A`, градиентная заливка.
- При открытии окна шапка уезжает вверх на 130 px, подвал вниз на 160 px с затуханием, контент уменьшается до 0.98 и гаснет — как `displaced-top / displaced-bottom / fade-out-content`.

Не перенесено (в WPF нет аналога CSS): letter-spacing у заголовка и кнопки «Играть», backdrop-blur у шапки и чипа новостей.


## Итерация v11 — скруглённое окно, версии Minecraft и режим «Все версии»

- **Скруглённое окно**: `AllowsTransparency` + рамка с радиусом 32 (как `.app-shell`). В развёрнутом виде углы становятся прямыми.
- **Реальные версии**: список релизов берётся из `version_manifest_v2.json` Mojang, картинки обновлений — из `javaPatchNotes.json` (`VersionCatalog.cs`). Картинки кэшируются в `%LocalAppData%\SubReel\cache\images`. Без сети показывается встроенный список и градиенты вместо картинок.
- **Первый запуск**: версия не сохранена → выбирается самый новый ванильный релиз, на фоне главной — картинка его обновления, над заголовком чип «MINECRAFT x.y.z / ПОСЛЕДНИЙ РЕЛИЗ». Выбор сохраняется в `%AppData%\SubReel\design-settings.json`.
- **Все версии**: колесо вниз на главной (или кнопка «Все версии») — шапка и подвал уезжают, снизу выезжают карточки групп (1.21, 1.20, …) с картинками обновлений. Назад: колесо вверх у начала списка, `Esc` или «Назад».
- **Меню подверсий**: клик по карточке «1.21» открывает список 1.21, 1.21.1 … 1.21.x с датами выхода; выбор меняет версию, фон и надпись в подвале. Если в группе одна версия — выбирается сразу.
- Группировка не зависит от схемы номеров: подходит и для `1.21.x`, и для `26.1.x`.


## Итерация v12 — главная как в референсе

- **Фон**: картинка обновления выбранной версии на всё окно, затемнение только слева под текстом и снизу. Картинка декодируется в 2200 px (карточки — 640 px) и рисуется с `BitmapScalingMode.HighQuality`; при смене версии плавно кроссфейдится и за ~2 с «встаёт на место» (лёгкий zoom-out).
- **Текст**: чип «Версия X уже в лаунчере!», заголовок «Твой мир. Твои правила.», описание, чип новостей — всё слева, элементы по очереди всплывают снизу при запуске.
- **Мини-информация об обновлении** (справа снизу): «Minecraft 1.21», номер версии и дата выхода, краткое описание из патчноутов Mojang (`shortText`, если есть), число версий в линейке.
- **Подсказка прокрутки**: «колёсико мыши» с бегающей точкой внизу по центру и индикатор страниц справа (главная / версии), по нему можно кликнуть. Анимации подсказки останавливаются, когда главная скрыта.
- **Профиль**: белая «пилюля» с аватаром, ником и стрелкой; стрелка поворачивается, под кнопкой выезжает меню — активный аккаунт, список добавленных (переключение, удаление), «Добавить аккаунт» (офлайн-ник: 3–16 символов, латиница/цифры/`_`), «Профиль», «Настройки». Аккаунты хранятся в `%AppData%\SubReel\design-settings.json`.
- Вход через Microsoft (код устройства) подключён в меню профиля; для работы нужен Client ID в `appsettings.json` (`Authentication:ClientId`), без него показывается «вход Microsoft не настроен». SubReel ID пока не подключён.


## Итерация v13 — фото, единый выбор версий, профиль в стиле лаунчера и задел под кастомизацию

**Фото**
- Пиксельная заглушка (`PlaceholderArt.cs`): у каждой карточки и у фона главной всегда есть картинка — и без сети, и для старых версий, у которых Mojang не даёт изображений. Узор зависит от номера версии, поэтому не «прыгает».
- Карточки: настоящее фото плавно проявляется поверх заглушки, при наведении мягко приближается (приближается сама картинка, углы остаются ровными). Затемнение под текстом вынесено из шаблона кнопки в код.
- `ImageCache`: картинка не растягивается сверх своего размера, битый файл в кэше удаляется и качается заново, две попытки загрузки, таймаут 30 с (у JSON-манифеста остаётся 10 с), не больше 6 загрузок одновременно, поддержка срока годности кэша (`maxAge`) — нужна для голов скинов.

**Версии**
- Кнопка «Версия» в подвале теперь открывает тот же экран «Все версии», что и колесо мыши (раньше это был отдельный плоский список всех релизов в белом ComboBox).
- Карточки разложены по секциям-годам (по первому релизу линейки), как на minecraft.net.
- Старые линейки без картинок (хвост списка, от 3 линеек) слиты в одну карточку «Старые версии»; в её меню каждая линейка — отдельная секция. В офлайне и при сбое патчноутов ничего не сливается.
- Названия обновлений (`Tricky Trials`, `Chaos Cubed`, `Wilderness Bound` …) показываются на карточке, в меню версий и над номером в карточке обновления. Таблица названий — `KnownLineTitles` / `KnownDropTitles` в `VersionCatalog.cs`.
- В каталоге `Lines` — настоящие линейки (1.21, 1.20, …), `Groups` — карточки (с «Старыми версиями»). `GroupOf` разделён на `LineOf` и `CardOf`.

**Профиль**
- Кнопка профиля больше не белая: тёмная пилюля `#141419` с тонкой рамкой, как остальные панели.
- Кастомизация (`Cosmetics.cs`, у каждого аккаунта своя `ProfileCosmetics`, хранится в `design-settings.json`):
  - ник: обычный / один цвет / градиент / радуга, при желании переливается;
  - рамка кнопки профиля: те же режимы + свечение;
  - аватарка: инициалы / голова скина по нику (minotar.net, кэш 12 часов) / своя картинка с диска.
- Редактор — «Профиль» → «Личный кабинет» → «Оформление профиля»: готовые стили, предпросмотр кнопки, изменения применяются сразу.
- Чтобы добавить стиль, достаточно новой строки в `NickPresets` / `FramePresets` (`MainWindow.Cosmetics.cs`). Чтобы подключить сервер — заполнять `ProfileCosmetics` из SubReel ID, отрисовка не меняется.

**Мелкие исправления**
- Настройки пишутся через временный файл — обрыв записи больше не стирает аккаунты.
- «Сохранить ник» проверяет формат ника (3–16, латиница/цифры/`_`) так же, как «Добавить аккаунт»; при ошибке рамка поля краснеет.


## v13.1 — поиск версий, «Недавние», предзагрузка картинок

- **Поиск** на экране «Все версии»: при открытии сверху съезжает строка поиска. Ищет по номеру (`1.20.4`), линейке (`26`) и названию обновления (`Tricky`); пустые секции скрываются, при отсутствии совпадений — «Ничего не найдено». `Enter` при точном номере сразу выбирает версию, первый `Esc` очищает запрос, второй — выходит назад.
- **Недавние**: под поиском — последние 6 выбранных версий (хранятся в `design-settings.json`, поле `RecentVersions`).
- **Предзагрузка**: сразу после загрузки списка, пока играет приветствие, лаунчер по 2 картинки за раз докачивает в кэш все картинки версий (`IImageCache.PrefetchAsync`, реализация `DiskImageCache`).


## Итерация v13.2 — страница версии

- Клик по карточке в «Все версии» больше не открывает маленькое меню: список плавно гаснет и чуть уезжает вверх, снизу выезжает полноценная страница версии (`MainWindow.VersionPage.cs`, разметка `VersionPage` в `MainWindow.xaml`).
- Слева: название обновления, «Minecraft 1.21», дата выхода, описание из патчноутов Mojang, выбор конкретной версии линейки (у «Старых версий» — по линейкам) и кнопка «Выбрать X». Справа: большая картинка обновления и галерея миниатюр (все разные картинки линейки, если у версий они свои); клик по миниатюре плавно меняет большую картинку.
- «Выбрать» меняет версию и возвращает на главную. `Esc`, «← Все версии» или `×` — назад к списку; колесо на странице не переключает режимы.
- Скриншотов, которых нет в каталоге Mojang, страница не выдумывает: если картинка у линейки одна, миниатюр не будет. Старое меню подверсий (`OpenVersionMenu`) осталось в коде, но не вызывается.


## Итерация v13.3 — выпадающий список версий, новости, SubReel Studio Hub

**Версии в подвале** (`MainWindow.VersionDropdown.cs`, `InstalledVersions.cs`)
- Клик по «Версия» открывает выпадающий список над кнопкой (как меню профиля). Раньше эта кнопка вела на «Все версии» — теперь каталог открывается пунктом «Все версии Minecraft» внизу списка, колесом мыши на главной и подсказкой прокрутки.
- В списке — **реально установленные** версии из `%AppData%\.minecraft\versions` (читаются только JSON-описания, ничего не скачивается): секции Vanilla / Fabric / Forge / NeoForge / Quilt / «Другие загрузчики». У каждой строки: версия Minecraft, загрузчик и его версия, статус «Установлена», галочка и подсветка у выбранной.
- Поиск идёт в фоновом потоке при каждом открытии списка; длинный список достраивается порциями, окно не подвисает. Позиция и размер списка подстраиваются под размер окна.
- Выбор сохраняется в `design-settings.json`: `SelectedVersion` (версия Minecraft — как раньше) и новое поле `SelectedInstallId` (папка версии, чтобы отличать Fabric от ваниля).
- Выбранная, но не установленная версия (например, выбранная из каталога) помечена жёлтым индикатором на кнопке и в списке; «ИГРАТЬ» для неё не запускает демо, а объясняет, что версии нет. Установка версий пока не подключена — её нужно делать вместе с игровым ядром.
- Нет папки игры или установленных версий — в списке понятное пустое состояние с путём.
- Иконки загрузчиков — нарисованные кубик (Vanilla) и цветные монограммы; при желании заменяются на логотипы в `BuildLoaderTile`.

**Новости** (`MainWindow.News.cs`, `NewsService.cs`)
- Чип «Свежие новости проекта» открывает отдельный экран: главная новость с обложкой, карточки остальных, категории-вкладки (Все / Новости SubReel / Новости Minecraft / Обновления лаунчера / Новости серверов / Моды и загрузчики), кнопка «Обновить», полная новость по клику.
- Выдуманные новости убраны. Источник сейчас один настоящий — заметки об обновлениях Java Edition от Mojang (категория «Новости Minecraft»). Остальные категории ждут источника SubReel: пока `NewsConfig.SubReelEndpoint = null`, они честно показывают «источник не подключён».
- Состояния: загрузка, ошибка с «Повторить», пусто, «нет связи — показаны сохранённые новости». Кэш — `%LocalAppData%\SubReel\cache\news.json` (свежий 20 минут).
- Подключение SubReel: задать адрес в `NewsConfig.SubReelEndpoint`; лента — JSON-массив вида
  `[{ "id": "...", "category": "subreel|launcher|servers|mods", "title": "...", "summary": "...", "body": "...", "imageUrl": "https://...", "url": "https://...", "publishedAt": "2026-10-30T12:00:00Z" }]`.
  Новый источник другого типа — реализация `INewsSource` и строка в `NewsSvc` (`MainWindow.News.cs`).

**SubReel Studio Hub** (`MainWindow.Hub.cs`)
- В шапке вместо «Настройки» — «Studio Hub». Страница: баннер, карточки Server Studio / Skin Studio / Mod Studio / «Другие инструменты», у всех статус «В РАЗРАБОТКЕ». Клик по карточке показывает уведомление «… пока в разработке», ничего не открывая.
- **Настройки** убраны из шапки, но остались полноценным разделом: «профиль в шапке → Настройки». Содержимое окна настроек не менялось.

**Не сделано / ограничения**
- Сборка не проверялась: окружение, где писался код, без .NET SDK. Нужно открыть решение в Visual Studio и собрать.
- Архитектура проекта — code-behind без MVVM и DI (так устроен весь концепт), поэтому новое сделано тем же способом: отдельные `MainWindow.*.cs` и независимые классы-сервисы (`InstalledVersionScanner`, `NewsService`), которые без изменений переедут в ViewModel/DI основного проекта.
- Настройки (память, автообновление) по-прежнему демонстрационные и не сохраняются — это было и до этой итерации.
