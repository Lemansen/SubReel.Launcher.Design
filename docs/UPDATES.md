# Автообновление лаунчера

Состояние: написано, ждёт сборки и проверки у владельца (`dotnet build`, `dotnet test`, затем живая проверка по списку внизу).

## Как это работает

1. При запуске и затем раз в `Updates:CheckIntervalHours` (по умолчанию 6) лаунчер скачивает JSON-манифест по адресу `Updates:ManifestUrl` (только https).
2. Если версия в манифесте новее текущей (`<Version>` в `Subreel.Launcher.Design.csproj`), справа сверху появляется баннер «Доступна версия X» с кнопками «Скачать» и «Позже». То же состояние видно в «Настройки → О лаунчере».
3. «Позже» прячет баннер этой версии на `Updates:SnoozeDays` (3) дня; более новая версия возвращает баннер сразу. Обязательные (`mandatory`) обновления отложить нельзя. Выбор хранится в настройках (`PostponedUpdateVersion`, `UpdateSnoozedUntilUtc`, `SchemaVersion` 2).
4. «Скачать»: архив качает общий Download Manager (докачка, повтор), затем проверяется SHA-256 из манифеста и распаковывается в `launcher\updates\<версия>`. Битый или подменённый архив удаляется, установка отменяется.
5. Лаунчер запускает копию `SubReel.Updater.exe` (папка `Updater` рядом с exe) и закрывается. Программа ждёт выхода лаунчера, сохраняет заменяемые файлы, копирует новые, запускает новый лаунчер. При сбое возвращает прежние файлы и запускает прежний лаунчер. Журнал — `launcher\logs\updater-ГГГГММДД.log`.
6. Папка данных пользователя (`%LocalAppData%\SubReel`) не затрагивается: заменяется только папка с exe. Остатки обновления удаляются при следующей проверке после запуска.

## Формат манифеста

```json
{
  "version": "1.2.0",
  "url": "https://updates.example.com/SubReel-1.2.0-win-x64.zip",
  "sha256": "64 шестнадцатеричных символа",
  "sizeBytes": 84500480,
  "mandatory": false,
  "releaseNotesRu": "Что нового"
}
```

- `url` — только https; узел должен совпадать с узлом манифеста или быть в `Updates:AdditionalDownloadHosts` (по умолчанию узлы GitHub Releases).
- В архиве обязан быть exe лаунчера (в корне или в единственной вложенной папке) и папка `Updater` с файлами `SubReel.Updater.*`. Сборка `dotnet publish` кладёт её сама.
- Хэш считать так: `Get-FileHash .\SubReel-1.2.0-win-x64.zip -Algorithm SHA256`.

## Ограничения

- Лаунчер в `Program Files` обновить нельзя (нет прав на запись): понятное сообщение, перенос в папку пользователя.
- Файлы, которых нет в новой версии, остаются на диске (удаление устаревших не делается).
- Подписи файлов нет: защита — https, список узлов и SHA-256 из манифеста. Манифест нужно хранить там, где его не подменят.

## Проверить вручную

1. Задать `Updates:ManifestUrl`, выложить манифест с версией выше текущей — баннер появляется.
2. «Позже» — баннер пропал, после перезапуска не появился; манифест с ещё более новой версией возвращает его.
3. «Скачать» на тестовом архиве: лаунчер закрывается и запускается новой версии; в журнале updater-*.log нет ошибок.
4. Испорченный sha256 в манифесте — сообщение о контрольной сумме, файлы не тронуты.
